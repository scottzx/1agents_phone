项目名称：疆行。让长途自驾，持续成行。
所选行业赛题：无界应用 / AI+汽车。
目标用户：自行组织新疆长途自驾的个人、伴侣或家庭旅行组织者。
核心问题：规划一趟新疆自驾并不难，难的是第 6 天它还成立吗。道路、天气、预约和同行人会变，酒店与机票承诺仍在。
解决方案：出发前建立 Trip Agent Graph，把路线、时间、费用、承诺与成行条件组织成可成行计划；途中传播影响、比较方案，用户确认后以最小扰动恢复成行；结束后沉淀用户可控记忆，进入下一趟旅行。初赛 Demo 为独库通行窗口冲突：可成行变为暂不可成行，比较提前出发与换候补路线，确认后更新路书与提醒并读回验证。基于 iagents_app / Minis，纯 iOS、本地优先，用户自选公有云模型。
创新点：管理 Plan 的生命周期，而非再生成攻略；一次变化沿 Graph 传播；记忆来自真实决策并由用户确认。
开放/复用价值：后续开放 Graph Schema、工具契约与示例旅行包，模型与地图可替换。
当前进展：总体方案与 PRD 已冻结；初赛交付简介、12 页 PPT 与交互原型；复赛实现可运行 iOS 闭环。不控制车辆，不替代交通与安全判断。

## 3. 场景来源与项目判断

### 3.1 场景来源

场景来自团队真实旅行经验：目的地“搜得到”不代表“今天能去”。周一闭馆、限时通行、需要提前预约、入口停止放行、临时道路事件和用户已购买的酒店/机票，都会让既有计划失效。现有地图、OTA、内容社区和日历分别解决单点问题，但用户仍需不断搜索、判断、比较并手工同步多个结果。

新疆自驾进一步放大了这一问题：距离长、承诺跨天、通行窗口和天气道路信息具有时效性，一次变化会传播到驾驶时长、补给、日照余量、住宿和后续数天。Agent 的价值不只是给答案，而是长期维护同一个旅行目标，在变化发生后继续把事情做完。

### 3.2 目标用户

自行组织新疆长途自驾的个人、伴侣或家庭旅行组织者。他们会跨多个平台做攻略和购买服务，用截图、PDF、短信或手动记录保存订单，并在旅途中承担全队协调责任。

### 3.3 五个核心痛点

1. **信息分散**：地图、公众号、官方公告、订单截图和个人笔记彼此割裂。
2. **信息会过期**：营业、预约、道路、天气与活动并非一次查询后永久有效。
3. **变化会连锁**：一个点位不可执行，会影响路线、酒店、补给和后续安排。
4. **执行靠手工**：做出决定后还要分别修改路书、导航、日历和提醒。
5. **每次从零开始**：作息、餐饮、驾驶方式、风险偏好和既往经历没有形成用户可控的长期记忆。

## 4. 产品定位与形态

一句话定位：**疆行持续维护自驾旅程的可执行性。**

疆行不是旅游社区、OTA、商家后台或泛聊天机器人，而是用户自己的“本地自驾操作系统”。用户可在任何渠道发现和购买服务，再把截图、PDF 或手工信息交给 Agent；系统负责组织承诺、持续调研、发现冲突、编排工具，并把确认结果交付到路线、路书和提醒。

产品为纯 iOS App：

- 首页是旅程 Command Center，展示当前阶段、下一站可执行性、Agent 长任务、待确认决策与最近回执；
- 路书按天组织路线、点位、酒店、补给和固定承诺；
- 证据收件箱接收语音、图片、PDF、链接和手工录入；
- 应变中心展示依据、备选方案、影响范围与人工确认；
- 行程结束后整理足迹、照片和旅行回忆短片，经预览确认后使用系统分享；
- Memory Center 管理日常节律、出行方式和跨旅程经历，允许确认、编辑、暂停和遗忘。

## 5. 大闭环套小闭环

### 5.1 跨旅程大闭环

灵感/资料 → 规划与承诺建模 → 出发前核验 → 导航与途中维护 → 动态调整 → 旅行完成 → 足迹/短片整理 → 分享 → 记忆进入下一趟旅行。

### 5.2 高频小闭环

- 下一站营业、预约或通行窗口核验；
- 沿途临时活动和餐饮发现；
- 道路、天气或延误导致的局部重排；
- 截图订单识别失败后的人工补录；
- 照片整理与旅行回忆短片预览。

每个小闭环都遵循同一协议：输入 → 理解约束 → 规划 → 调用工具 → 带依据交付 → 用户确认 → 写入并验证 → 回执/撤销 → 反馈与候选记忆。

## 6. 核心 Demo：独库通行窗口与预约冲突

### 6.1 初始状态

- 用户计划明天从独山子进入独库公路，原计划 19:30 到达入口；
- 当前没有完成预约；
- 当晚住宿和后续行程已固定；
- 用户明确偏好“不赶夜路，重要通行窗口优先”。

### 6.2 Agent 执行

1. 接收“帮我检查明天路线是否还能走”的自然语言任务。
2. 从路书读取入口时间、酒店承诺、同行人和长期偏好。
3. 检索新疆文旅/公安公开信息，提取通行窗口、预约要求、发布时间与适用范围。
4. 调用高德路线能力估算出发时间、抵达时间、绕行和后续影响。
5. 发现“计划抵达时间晚于放行窗口，且未预约”的冲突。
6. 输出两个结构化方案：提前出发并预约；保留出发节奏并改走候补路线。
7. 展示依据、新鲜度、不确定项、影响对象和需要用户确认的动作。
8. 用户确认后，系统才更新路线、路书和提醒；读回验证并生成回执、Undo。
9. Agent 提出候选记忆：“长途自驾优先保证通行窗口和日落余量”，由用户决定是否保存。

### 6.3 失败与缺失信息

- 官方来源无法访问：明确显示“无法确认”，保留原计划，不以模型猜测替代事实；
- 高德接口失败：展示最近一次可信快照及更新时间，允许稍后重试或手动输入；
- 无官方预约接口：只提供官方入口和操作清单，不模拟成功、不代替用户提交；
- 截图提取不稳定：要求用户选择字段或手工补录；
- 写入任一系统对象失败：显示部分成功状态并允许重试、对账或撤销。

## 7. Agent 能力逐项证明

| 要求能力 | 在 Demo 中的可验证表现 |
|---|---|
| 任务理解 | 识别“检查路线”的真实目标是判断明日行程可执行性，而非只做路线搜索 |
| 多轮交互 | 缺少预约状态、出发弹性时主动追问；用户可比较、修改后再确认 |
| 任务拆解 | 拆成约束读取、官方检索、路线估算、影响传播、方案比较和提交验证 |
| 工具调用 | 调用网络检索、高德路线、旅行文件、Calendar、Reminders 和 Native Offload |
| 知识增强 | 以官方公告/规则为证据，保留来源、发布时间、适用范围和新鲜度 |
| 上下文管理 | 同一 tripId 保存承诺、任务 checkpoint、事件、待确认 ChangeSet 和回执 |
| 流程编排 | 先核验事实，再算路线，再比较影响；关键写动作必须等待用户确认 |
| 结果交付 | 输出结构化方案、依据、变化清单，并同步路线、路书和提醒 |
| 验证反馈 | 读回本地和系统对象，记录日志、回执、失败状态和 Undo；真实选择生成候选记忆 |

## 8. 工具、数据与知识增强

| 能力/数据 | 初赛方式 | 复赛接入 | 授权、处理与失败边界 |
|---|---|---|---|
| 高德地图 | 原型使用明确标注的模拟路线数据 | iOS 地图/导航 SDK 或 Web 服务，按正式授权范围接入 | 仅用于手机端路线、搜索和导航辅助；遵守隐私合规要求，不用于车控、模型训练或自建地图数据集 |
| 官方公开信息 | 原型使用已核验的新疆文旅/公安公开页面摘要 | 网络检索工具访问官方网页 | 展示来源、发布时间、访问时间与适用范围；不可访问时不猜测 |
| 用户资料 | 脱敏截图/PDF/手工样例 | Share Extension、附件解析、OCR/视觉模型 | 最小化上传；原件默认本地；用户可编辑和删除；无授权数据不使用 |
| iOS 上下文 | 原型模拟位置、时间和日程 | Location、Calendar、Reminders、Photos、Share Sheet | 按需申请最小权限；写入、位置与分享均可撤销/关闭 |
| 长期记忆 | 原型展示候选与确认流程 | 本地 Memory Store + 来源/置信度/范围 | 一次行为不自动成为永久画像；可确认、修改、暂停和遗忘 |

初赛不建设大而全的旅游知识库。动态事实优先检索官方来源，用户承诺来自用户输入，本地保存结构化旅行状态；来源不确定时由用户补录或确认。

## 9. 模型、Runtime 与上下文

### 9.1 初赛冻结模型

- **推荐主模型**：阿里云百炼 `qwen3.8-max-preview`（闭源预览模型）。
- **调用范围**：意图与约束理解、截图/图片理解、任务规划、工具选择、结构化输出和结果解释。
- **接口方式**：公有云 API，比赛 Demo 固定模型 ID、接口类型、推理模式与关键参数。
- **费用假设**：由演示者账号承担调用费用；Token Plan/Credits 或按官方公示计费，报名材料不承诺永久免费。
- **风险披露**：预览模型版本可能变化；真实 Demo 需记录调用时间、模型 ID 和关键输出。
- **替代方案**：`deepseek-v4-pro` 承担文本推理、任务拆解和 Tool Calls；图片需组合独立视觉模型或本地 Vision Skill。Provider 抽象降低迁移成本。

模型不负责确定性事实和真实写操作：路线时间由地图工具计算，规则由带来源的检索结果提供，Calendar/Reminders/媒体处理由受控工具完成，写入后必须读回验证。

### 9.2 Runtime 与状态

现有 iagents_app / Minis 已支持多模型 Provider、工具循环、附件、多轮会话、Memory、Skills 和 Native Offload。比赛新增的是旅行 Flavor、旅行文件夹、操作日志、快照、提交回执和恢复协议。

核心任务状态为 `planned / running / waiting_event / waiting_user / paused / failed / completed / cancelled`。iOS 不假装永久后台运行，而是在用户动作、分享扩展、本地通知、机会性后台刷新或再次前台打开时，从 checkpoint 恢复长期任务。

### 9.3 三层记忆

1. 日常节律：餐饮、作息、休息和行程密度；
2. 出行方式：自驾、跟团、摩托、飞机、高铁及驾驶风险偏好；
3. 跨旅程经历：去过哪里、喜欢什么，本次要重复、深化、对比还是避开。

记忆具有来源、置信度、适用范围和状态。当前行程的明确要求高于长期记忆；敏感健康信息单独授权，不进入通用画像。

## 10. 合规、安全与知识产权边界

- 不控制车辆、不接入车辆安全控制、不参与自动驾驶或替代驾驶员判断；
- 驾驶中采用轻量语音播报，复杂比较、预约、支付和编辑要求停车后完成；
- Agent 不自动修改路线，不自动预约、购买、发布或报警；高影响动作均需明确确认；
- 只有存在官方接口且权限充分时才可辅助预约，提交前展示对象、时间、费用和取消条件；
- 输出显示来源、更新时间、适用范围和不确定性；模型幻觉不能作为道路与营业事实；
- 用户位置、照片、订单、联系人和健康资料采用最小权限、本地优先、可删除设计；
- 初赛 Demo 使用模拟/脱敏数据并明确标注，不伪装为真实接口执行；
- 高德、模型、系统 API 和开源依赖在复赛材料中披露版本、许可证、权限和可替代性；
- TREK 仅作为旅行领域公开参考，不复制其 AGPL 源码、部署、品牌、UI、数据或视觉资产；比赛实现独立基于 iagents_app / Minis。

## 11. 初赛 Demo 视频脚本（90–150 秒）

### 0–20 秒：建立真实任务

打开明日独库行程。首页显示“计划 19:30 抵达入口、尚未预约、当晚住宿已确认”。用户说：“帮我检查明天路线还能不能走。”

### 20–55 秒：Agent 调研与解释

展示任务拆解和工具调用：读取路书 → 检索官方规则 → 调用高德路线 → 检查后续承诺。结果显示通行窗口冲突、预约缺失，并列出来源与新鲜度。

### 55–90 秒：比较与人工确认

比较“提前出发并预约”和“候补路线”两个方案。用户选择前者，预览变更：出发时间、路线、午餐点和提醒；再次确认。

### 90–115 秒：结果交付与验证

路书、路线和提醒更新后读回验证；展示 commit 回执、操作日志与 Undo。强调任何路线变更都不是自动发生。

### 115–140 秒：大闭环伏笔

Agent 提议候选记忆；切到旅途结束后的照片整理/回忆短片预览，再展示下一趟旅行如何询问是否沿用该偏好。

## 12. 验证指标

- 同一 tripId 跨多个时间点和 App 重启可恢复；
- 官方信息、路线计算和用户承诺均能追溯来源与更新时间；
- 一次冲突至少影响路线、路书、提醒三个对象，并在确认后读回一致；
- 同一 operationId 重试不重复写入；任一步骤失败可解释、重试或撤销；
- 无网时可查看最近一次可信路线、今天/明天安排、订单凭证与联系人；
- 候选记忆引用真实 decision/action ID，下一趟旅行实际读取且允许覆盖；
- 评测保留截图、日志、回执、错误分支和演示视频作为证据。

## 13. 项目基础、开放计划与落地路线

按普通软件路径推进，不绑定租车履约，也不以捐赠作为交付高潮。

### 冷启动

- 先做一条北疆线，以独库为切口；种子用户是会自己组队的车主。
- 交付 500 字简介、PPT/PDF 与单文件交互 HTML。
- 出发前能排出证、约、关闸；用模拟/脱敏数据跑通独库小闭环。
- 冻结比赛模型、接口范围、费用假设和第三方依赖说明。

### 试运行

- 真实出发前核验 + 途中弱网，收集「约不上 / 打不开 / 断网」。
- 失败分支可解释，离线包在无网时可读。

### 正式运行

- 基于现有 iagents_app / Minis 实现 iOS 旅行 Flavor。
- 接入高德、官方网络检索、附件/视觉理解、Calendar 和 Reminders。
- 实现旅行文件夹、任务 checkpoint、幂等提交、读回验证和 Undo。
- 同一条旅程跨重启仍在；提交可运行工程、样例数据、日志与复现说明。

### 扩大推广

- 从一条线扩到更多新疆自驾线，新线路套同一套约束表和工具契约。
- 开放旅行包 JSON Schema、工具契约、操作日志、记忆模型和安全边界模板，方便复现而不是另做平台。
