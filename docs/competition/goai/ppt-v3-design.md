## 1. 这套 PPT 要完成的任务

GOAI 初赛方案 PPT 是评委 **静默阅读** 的材料，不是现场带节奏的路演本。手册要求说清八件事：

场景来源 · 用户痛点 · 核心流程 · 产品形态 · Agent 能力 · 工具 / 数据 / 模型使用方式 · 合规边界 · 后续落地计划

初赛评分里，行业场景价值 25%、Agent 能力与任务闭环 25%、产品体验 20%。因此 v3 的设计任务不是「把 PRD 缩进幻灯片」，而是：

1. 让评委 10 秒内知道这是一个 **车主自己用的本地软件**，核心问题是「今天这条线还能不能走」。
2. 让八项要求可以按页眉对勾，不必在全文里找。
3. 让「为什么必须是 Agent」成为一个 **判断页**，而不是能力名词堆砌。
4. 让 Demo 证明绳子在工作：一次变化同时碰到预约、关闸、路书、提醒，而不是又演示了一个预约功能页。

## 2. 总设计理念

### 2.1 从小切到大，不从宏观切到用户

v1 / v2 的问题是：先讲旅游兴疆、信息孤岛、持续可执行性，再落到独库。评委听到的是报告词，后面的产品动作就会显得飘。

v3 反过来：

| 层 | 评委先听到 | 刻意后置或删除 |
|---|---|---|
| 小 | 边防证、独库预约、19:00 关闸、300 公里没油没信号、四个人对不齐 | 旅游兴疆、产业援疆、运营中心 |
| 中 | 出发前一张表、路上一句判断、回来对得上 | 食住行游购娱六板块 |
| 大 | 本地 iOS Agent，同一条线持续核验 | 捐赠、项目组交接、租车履约 |

封面主句因此不是「持续维护自驾旅程的可执行性」，而是用户原话收束后的产品句：

**按你的路线，告诉你今天还能不能走。**

### 2.2 五件难受是珍珠，Agent 是绳子

团队对「如果今天去新疆自驾，最难受的是什么」给出了五条非常具体的答案：

1. **约束一直在变**：边防证、独库开没开、喀纳斯不让私家车进、两点之间 300 公里没油没信号。
2. **情报过期**：出发前全是去年攻略，路上还得自己盯五六个公众号。
3. **一出城就断网**：导航没预载、支付扫不了、抛锚叫不到人。
4. **预约被拆散**：独库北段、景区票、边防证各一个小程序；北京时间和关闸对不上，天还亮着 19:00 已经不让进。
5. **人不同步**：四个人四个号，有人忘办证、有人没约上，天气一变群里吵到天黑。

这五件事看起来像五个功能，传统做法会做成五张表、五个模块。团队此前参与过「驭见新疆」全域自驾车旅游服务体系项目前期工作，知道这条路的结局：

- 每个入口单独看都成立；
- 规则一变要改五处；
- 一个人没约上，另外四张表不会自己变红；
- 一出城断网，五个模块各自残缺；
- 明年再变，就再加第六、第七个功能。

**难的不是做出这五个入口，是它们不会互相改。**  
若用传统工程把「一直盯着这条线」做成可维护，成本接近自建一个永不下班的运营中台。

所以 Agent 不是第六个功能。它是绳子：在同一条路线、同一个 `tripId` 上，把证、约、关闸、油站、人串起来，压成一句「还能走 / 走不成」，等人确认后再写回路书、提醒和离线包。珍珠可以继续增加，绳子不用重做。

这一判断是整本 PPT 的腰，单独占第 4 页。

### 2.3 角色必须先切干净

旧可研的宏观命题是「全域自驾服务体系」：租车、网点、数据中台、运营调度。今天的作品只切 **车主组织出游** 这一刀。

- 用户在任意渠道订票、订房、租车。
- 疆行不卖服务、不做 OTA、不当商家后台、不替用户提交预约。
- 产品是用户自己手机里的本地软件：纯 iOS、本地优先、无自建业务服务器。

旧项目只在「场景来源」和「为什么是 Agent」里各出现半句，用来证明不是比赛周才发明场景，也证明「堆功能」这条路走过。中间页和结尾不再提「驭见新疆」，避免评委把本作品理解成租车平台换皮。

### 2.4 落地按普通软件讲

不讲捐赠、不讲项目组交接。四段就是常见软件路径：

冷启动一条线 → 试运行收集失败 → 正式运行接真工具 → 扩大推广套同一根绳子。

## 3. 与手册八项的页映射

页眉直接写官方词，方便静默阅读时对勾。

| 页 | 官方标签 | 设计上只回答一件事 |
|---|---|---|
| 1 | 封面 | 这是什么 |
| 2 | 场景来源 | 场景从哪来，卡住的是哪些具体事 |
| 3 | 用户痛点 | 五件事为什么是同一张待办 |
| 4 | 用户痛点 / 产品判断 | 为什么不是 5 个功能，而是 Agent |
| 5 | 产品形态 | App 有哪些界面，分别对着哪件难受 |
| 6 | 核心流程 | 总流程只讲一套 |
| 7 | 核心流程 · Demo | 先证明明天走不成 |
| 8 | 核心流程 · Demo | 确认后才写入并读回 |
| 9 | Agent 能力 | 九项能力在 Demo 哪一步能看见 |
| 10 | 工具 / 数据 | 谁给事实、怎么授权、失败怎么办 |
| 11 | 模型使用方式 | 模型做什么、不做什么 |
| 12 | 合规边界 | 汽车红线 + 数据 + 模拟标注 |
| 13 | 落地计划 | 冷启动到推广，并收束主张 |

评委若按清单扫：前 4 页完成「场景 + 痛点 + 为什么是 Agent」，5–8 页完成「形态 + 流程 + 可验证闭环」，9–12 页完成技术与合规披露，13 页完成可行性。

## 4. 视觉与写作系统

### 4.1 版式

- 画幅 13.333" × 7.5"（16:9），延续 v2 的竞赛阅读比例。
- 白底、细线卡片、少量海军蓝收束条。不是深色科技风，也不是旅游宣传册。
- 页眉：官方标签（蓝）+ 主标题（黑）+ 一句副标题。不用装饰性下划线。
- 页码两位数字，右下弱化。
- 主字体 PingFang SC。强调色：蓝 `#2867F0` 用于主行动和绳子；琥珀 `#C46A00` 用于冲突、关闸、人工确认；绿 `#087D55` 用于 Agent 侧与通过；红 `#B93838` 用于传统做法失败和合规红线。

### 4.2 写作

- 优先用人说过的词：关闸、约上、证带没带齐、群里吼、下死、标红。
- 少用：赋能、闭环生态、一站式、智慧大脑、信息孤岛（除非在对比传统方案时作为被替代的旧词）。
- 数字分两类：规则引用公开通告（独库预约、19:00 窗口）；ETA / 出发时刻标明模拟。
- 「驭见新疆」全稿只许出现在第 2、第 4 页。
- 正文不许出现捐赠、援疆指挥部、车辆投放、阿拉尔运营中心、租车下单。

### 4.3 原型图怎么用

只在需要「这是真的 App，不是概念图」的页放截图：

- 封面 / 产品形态：首页 Command Center
- Demo 核验：调研与证据页
- Demo 写入：回执页

记忆中心、旅行短片不做主视觉。它们是大闭环伏笔，不是初赛主线。

## 5. 逐页设计内容

### 第 1 页 · 封面

**设计意图**  
开场只建立一个产品身份，不讲政策，不讲旧项目，不讲捐赠。

**页面内容**

- 赛题：GOAI · 无界应用 / AI+汽车
- 产品名：疆行
- 形态：本地自驾 Agent
- 主句：按你的路线，告诉你今天还能不能走
- 解释：证齐没齐、约上没约、油和信号够不够；出发前能看见，路上还继续核
- 形态标签：纯 iOS · 本地优先 · 无自建业务服务器 · iagents_app / Minis
- 右侧：首页原型

**为什么这样**  
评委如果只看一页，应带走「车主软件 + 今天能不能走」，而不是「又一个新疆文旅平台」。

---

### 第 2 页 · 场景来源

**设计意图**  
场景来源必须同时回答三个问题：从哪知道的、现场卡在哪、今天只切哪一刀。用时间三列摊开，不用抽象阶段词单独成页。

**页面内容**

- 标签：场景来源
- 标题：出发前、路上、回来，卡住的是这些事
- 来源句：团队此前参与「驭见新疆」全域自驾车旅游服务体系项目前期工作。更直接的来源，是自己和身边人反复走新疆时卡住的那几件。
- 三列：
  - **出发前**：去年攻略还在用，今年独库要预约、边防证改电子；独库北段 / 景区票 / 边防证各一个小程序，少约一个就劝返；四个人四个号，有人忘办证、有人没约上
  - **路上**：天气一变当天作废，还得自己刷五六个公众号；天还亮着，19:00 独库已经关闸；一出城断网，导航没预载，抛锚也叫不到人
  - **回来**：票根、预约码和照片对不上；下次还是从零翻聊天记录；没有人记得这条线当年卡在哪
- 收束条：想要的不是更多攻略。是按这条线，实时回答：今天还能不能走、证带没带齐。

**故意不写**  
可研里的游客量、40 万辆车、五级网点、阿拉尔选址、一期投资。那些是旧项目的规模，会把今天的切口撑爆。

**事实锚点**  
独库北段预约、社会车辆 8:00–19:00 通行、边防证电子化、喀纳斯旺季私家车不能进核心区，均可被公开材料核对。PPT 用它们当「这不是编的」，不把通告全文铺上去。

---

### 第 3 页 · 用户痛点

**设计意图**  
把第 2 页的散装难受收成一张待办。本页 **只定义问题**，不展开 Agent。

**页面内容**

- 用户：自行组织新疆长途自驾的个人、伴侣或家庭旅行组织者。不是游客画像，是旅程负责人。
- 判断句：他们不是缺功能，是没人按「你这条线」把事情收齐。
- 五列对照：

| 难受 | 现在怎么熬 | 想要的最小结果 |
|---|---|---|
| 约束一直在变 | 边防证、独库开没开、喀纳斯不让私家车进，全靠记忆 | 按路线列出今天卡你的那几条 |
| 情报过期 | 去年笔记 + 临时刷公众号 | 官方路况 / 预约 / 油站压成一句判断 |
| 预约互不相通 | 五个小程序，提前天数还不一样 | 排出哪天几点前必须约上哪个码 |
| 一出城就断网 | 命绑在一格信号上 | 出发前把地图、油站、救援点下死 |
| 人不同步 | 微信群里对证、对约、对今晚住哪 | 证 / 约 / 油 / 人一张表，谁缺什么当天看得见 |

- 底栏：地图、OTA、公众号、日历各管一段；没有入口按你这条线收成「今天能不能走」。所以下一页必须回答：为什么不能做成 5 个功能。

**为什么拆成第 3、第 4 两页**  
痛点和形态选择挤在一页，评委会以为我们只是在抱怨。分开后，第 3 页让人点头「就是这样」，第 4 页再抛判断。

---

### 第 4 页 · 为什么是 Agent（全稿腰部）

**设计意图**  
这是整本最重要的一页。要让评委同意：我们不是不会做那五个功能，是做了也维护不住。

**页面内容**

- 标题：不是再做 5 张表，是用一根绳子把它们串起来
- 经验句：团队以前参与过「驭见新疆」相关前期工作。开一个 App、堆一个功能，这条路走过：散装、打不通、不可维护。

**左：传统 5 模块（红底，彼此断开）**

| 模块 | 单独看时好像成立 |
|---|---|
| 约束清单 | 边防证 / 独库 / 喀纳斯 |
| 资讯聚合 | 公众号和通知 |
| 预约日历 | 哪个码哪天截止 |
| 离线包 | 地图和油站 |
| 同行人表 | 谁缺证、谁没约 |

结论：难的不是做出这 5 个入口，是它们不会互相改。

**右：Agent 是绳子（绿底，五颗珠子穿在一条线上）**

珠子：证 · 约 · 关闸 · 油站 · 人

绳子上的动作：

1. 读你的路和人  
2. 查出今天卡你的规则  
3. 对上预约和关闸  
4. 看谁缺什么  
5. 压成一句「还能走 / 走不成」  
6. 人点头后再改路书、提醒、离线包  

结论：规则明年再变，加的是新珍珠。绳子不用重做。

**底栏对照**

- 传统：人自己在页面之间搬运状态；规则一变，改 5 处。
- Agent：同一 `tripId` 上持续对齐。产品停在「今天能不能走，确认后写进去」。
- 金句：珍珠可以继续增加。没有绳子，多一颗就多一个散装功能。Agent 就是那根绳子。

**设计隐喻为什么用珍珠 / 绳子**  
珍珠是领域对象，可以增减；绳子是跨对象的状态对齐。评委以后看到边防证、独库、关闸，应想到「又是一颗珍珠」，而不是「又要新开一个模块」。

### 第 5 页 · 产品形态

**设计意图**  
五个界面必须能一一对上第 3 页的五件难受。首页必须出镜，因为它是绳子经过的地方。

**角色边界（页顶先写）**  
这是车主自己手机里的软件。机票、酒店、租车仍在原渠道买。疆行不卖服务、不做 OTA、不当商家后台。

**界面与痛点映射**

| 界面 | 对着哪件难受 | 这一屏负责什么 |
|---|---|---|
| 今日能否走（首页） | 情报过期 + 约束在变 | 下一站能不能走、Agent 在等什么 |
| 预约与关闸日历 | 号是拆开的，19:00 ≠ 天黑 | 哪天几点前必须约上哪个码 |
| 证 / 约 / 油 / 人表 | 四个人对不齐 | 谁缺什么，当天标红 |
| 出发前离线包 | 一出城就孤岛 | 地图、油站、救援点、今日明日行程 |
| 应变中心 | 天气一变，当天作废 | 依据、方案、影响；人确认后再写 |

**驾驶态**  
不单独做一页。原则写在应变里：只播「还能走 / 该提前 / 该停」；改计划、补预约停车后再做。

**故意降权**  
Memory Center、足迹短片不占主视觉。回来对账在流程页用一句话交代即可。

---

### 第 6 页 · 核心流程

**设计意图**  
全稿只保留一套流程语言。不再同时出现「八步大闭环」和「七步小闭环」两套词，避免评委自己对齐。

**主流程（评委要记住的）**

1. **出发前**：导入路线和截图 → 生成约束清单、预约截止时刻、离线包 → 同行人缺项标红  
2. **路上**：规则或天气一变，只重算今天和下一站 → 一句「还能走 / 走不成」+ 依据 → 人确认后再改路书和提醒  
3. **回来**：票根、预约记录、照片挂回同一条旅程 → 下次不用从零翻群 → 真实选择变成候选记忆  

**小闭环协议（脚注级，只出现一次）**  
输入 → 核验约束 → 调用工具 → 带依据交付 → 人工确认 → 写入读回 → 回执 / 撤销  

初赛验证的是路上那一个小闭环（独库），不是把出发前到回来全部做完。记忆是伏笔。

---

### 第 7 页 · Demo：先证明走不成

**设计意图**  
Demo 台词必须来自痛点，不能写成「发现风险」。核出来的是三件具体的事。

**任务**  
用户：「帮我检查明天路线还能不能走。」  
路书：明天独山子进独库，计划 19:30 到入口。

**三件核出来的事实**

1. **还没约**：北段要预约，本车还没有号。  
2. **会吃闭门羹**：社会车辆 19:00 后不让进，19:30 到入口会关在门外。  
3. **后面会挤**：当晚住宿已定，往前赶会挤午餐和日照余量。

**证据与失败**  
依据来自公开通告，标发布时间。官方打不开就写「无法确认」，不拿去年攻略顶上。路线与 ETA 为原型模拟数据。

**为什么选独库**  
一条切口同时打中：情报过期、预约拆散、关闸 ≠ 天黑、变化会传到住宿。不必另开三个 Demo。

---

### 第 8 页 · Demo：确认后才写入

**设计意图**  
证明绳子在工作。一次确认必须同时碰到多颗珍珠，且 Agent **不代替**用户去小程序提交预约。

**写入对象**

| 对象 | 变化 |
|---|---|
| 路线 | ETA 19:30 → 17:40 |
| 路书 | 出发 18:00 → 16:10 |
| 提醒 | 补上必须约上的那个点 |
| 同行人表 | 预约未完成仍标红 |
| 离线包 | 带上今日路线、油站、救援电话 |

**工程语义（给技术评委）**  
`committed` · 读回一致 · 可撤销 · 同一 `operationId` 不重复写。  
没有官方预约接口时只给官方入口和操作清单，不模拟预约成功。

这一页把第 4 页的隐喻收成可验证动作：珍珠被同一根绳子改写，且有回执。

---

### 第 9 页 · Agent 能力

**设计意图**  
对照赛道能力清单，但每格只写「Demo 里哪一步能看见」。禁止能力名词空转。

| 能力 | 在 Demo 中的证据 |
|---|---|
| 任务理解 | 「检查路线」被理解成明日能不能进独库，不是再搜一条路 |
| 多轮交互 | 缺预约状态、出发弹性时追问；用户可比较后再确认 |
| 任务拆解 | 约束 → 官方检索 → 算路 → 影响 → 方案 → 提交 |
| 工具调用 | 旅行文件、网络检索、高德、日历、提醒 |
| 知识增强 | 公安厅通告带来源、发布时间、适用范围 |
| 上下文管理 | 同一 tripId 保存承诺、checkpoint、ChangeSet、回执 |
| 流程编排 | 先核验关闸和预约，再算路，再等人确认 |
| 结果交付 | 一句判断 + 同步路线、路书、提醒 |
| 验证反馈 | 读回、日志、Undo；预约未完成仍标红 |

### 第 10 页 · 工具 / 数据

**设计意图**  
先立总原则，再列表。原则比表格更重要：

**官方给事实，高德做计算，旅行包保存承诺，用户做高影响决定。模型不编关闸时间。**

| 能力 | 用来干什么 | 授权与处理 | 失败时 |
|---|---|---|---|
| 高德地图 | 路线、ETA、搜索、导航入口 | 初赛模拟；复赛按手机端正式授权 | 最近可信快照 / 手工输入 |
| 官方检索 | 通行、预约、营业、临时规则 | 只接受可追溯公开来源 | 无法确认，不猜测 |
| 用户资料 | 截图、PDF、订单、手工承诺 | 原件默认本地，最小化上传 | 提取失败则用户补录 |
| 同行人表 | 证 / 约 / 油 / 人是否齐 | 只存在用户自己的旅程里 | 缺项标红，不代提交 |
| 离线包 | 地图、油站、救援点、今日明日 | 出发前写进本机 | 无网可读，不假装能现场预约 |
| iOS 系统 | 位置、日历、提醒、相册 | 按需最小权限，写入需确认 | 部分失败则对账 / 重试 / Undo |

**故意不写**  
政务云、微服务中台、租车车辆主题库、支付中台。那些是旧可研的数字化建设，不是今天作品的架构。

页脚：不建设大而全旅游知识库。动态事实查官方，现实承诺由用户提供，结构化旅行状态留在本地。

---

### 第 11 页 · 模型使用方式

**设计意图**  
满足手册对闭源模型、商业 API、可替代性的披露，同时把模型从「真相来源」里拿出去。

**Runtime（已有，不是为比赛新造）**  
iagents_app / Minis：多模型 Provider、工具循环、附件、多轮会话、Memory、Skills、Native Offload。  
比赛新增的是旅行文件夹、操作日志、快照、checkpoint、ChangeSet、回执。

**模型分工**

- 推荐：Qwen3.8-Max Preview。用于意图、截图理解、规划、Tool Calling、解释。闭源预览，演示者账号付费，版本需冻结。
- 替代：DeepSeek-V4-Pro。文本推理与 Tool Calls；图片另配视觉能力。
- Provider 可替换，旅行状态和工具契约保持稳定。

**模型明确不做**  
关闸时间、预约规则、ETA、系统写入、结果验证。这些由官方来源和确定性工具给出。

**记忆（一行，不当主线）**  
L1 日常节律 · L2 出行方式 · L3 跨旅程经历。必须有来源、范围、置信度和用户控制。一次行为不自动变成永久画像。

### 第 12 页 · 合规边界

**设计意图**  
汽车赛题红线独立成页，不和开放复用、落地计划混在一起。写成产品门禁，不写成价值观海报。

| 红线 | 产品里怎么落 |
|---|---|
| 不控车 | 不接入车辆安全控制，不参与自动驾驶，不替代驾驶判断 |
| 不代办 | 不自动改路线，不代提交独库预约，不代办边防证，不代下单 |
| 不在驾驶中做复杂决定 | 只播「还能走 / 该提前 / 该停」；改计划停车后再做 |
| 不拿幻觉冒充道路事实 | 无法核验就写「无法确认」，不拿去年攻略顶上 |
| 数据最小权限 | 位置、照片、订单、联系人本地优先，可删除 |
| 应急由人触发 | 只组织电话和位置，报警和导航由用户自己拨 |

页脚：初赛原型显著标注模拟数据，不伪装成真实接口执行。

### 第 13 页 · 落地计划 + 收束

**设计意图**  
按普通软件推广讲，证明这是一个可迭代的本地产品，不是一份只能比赛用的概念书。结尾回到第 2 页的人话，不升调。

| 阶段 | 做什么 | 验证什么 |
|---|---|---|
| 冷启动 | 一条北疆线，独库为切口；种子用户是会自己组队的车主 | 出发前能排出证、约、关闸；原型可点 |
| 试运行 | 真实出发前核验 + 途中弱网 | 约不上 / 打不开 / 断网可解释；离线包真能用 |
| 正式运行 | iOS 接高德、官方检索、系统工具 | 写入可撤销，跨重启还在 |
| 扩大推广 | 从一条线扩到更多新疆自驾线 | 新线路套同一根绳子，不重做 App |

**收束句**

> 最难受的不是风景。是约束一直在变，情报一直在过期，人一直对不齐。  
> 疆行做的事很窄：按你这条线，告诉你今天还能不能走。  
> 本地自驾 Agent · 用户拥有数据和最终决定权。

## 6. 与旧项目、PRD、原型的关系

| 材料 | 在 PPT 里的地位 |
|---|---|
| 「驭见新疆」可研第 2、3、5 章 | 宏观命题和数字化旁证。只继承游客侧的执行痛苦，不继承租车、支付、调度、网点。 |
| PRD | 信息架构、任务状态机、提交协议、记忆模型的后台依据。PPT 不搬文件夹结构和 CLI。 |
| 交互原型 HTML | Demo 页的视觉证据。PPT 声明模拟数据，与原型标注一致。 |
| v1 / v2 PPT | v1 贡献了「单点工具 vs 长期负责」；v2 贡献了工具表和模型披露。v3 把判断收成珍珠 / 绳子，把痛点换成真人原话。 |

## 7. 以后改页时必须守住的约束

1. 封面主句保持「今天还能不能走」，不要退回「可执行性」「智慧旅游」这类空词。
2. 第 4 页不能删、不能降成痛点页的脚注。没有这一页，后面全是功能展示。
3. Demo 必须一次碰到至少三颗珍珠。只演示预约页或只演示导航，等于自己打脸。
4. 不代约、不代办证、不控车，写进产品，不只写进合规页。
5. 记忆和短片继续当伏笔。
6. 「驭见新疆」不加第三处。落地不加捐赠。
7. 新增能力先问：这是新珍珠，还是绳子的新动作？若是新珍珠，不要新开模块页。

---

## 8. 一句话总设计

疆行 PPT 不推销新疆，不推销租车，不推销一个大而全的旅游操作系统。它只设计一件事：

**把车主已经在手工拼接的证、约、关闸、油站和人，收进同一条线上；用 Agent 当绳子去对齐它们；产品停在「今天能不能走」，确认之后才写进手机里。**
